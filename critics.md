# Trading Strategy Review: Replacing Debate Engine with Data-Driven Learning

## Executive Summary

The current trading platform has evolved beyond a simple signal-generation system. It now resembles a portfolio decision-support framework with:

* Risk management
* Confidence calibration
* Thesis tracking
* Learning loops
* Validation logic
* Portfolio controls

The system's next stage of development should focus on extracting more value from real trading outcomes rather than introducing additional AI debate mechanisms.

The existing dataset generated by executed trades is significantly more valuable than feedback from a secondary small language model.

The highest-return improvements involve:

1. Driver-level performance analysis
2. Regime-aware learning
3. Entry-condition optimisation
4. Exit-tag analytics
5. Pattern-based calibration
6. Automated strategy playbooks

# Why the Debate Engine Should Be Deprioritised

## Current Assumption

The debate engine attempts to improve recommendations through:

```text
Bull AI
vs
Bear AI
```

or

```text
Claude
vs
Local LLM
```

## Problem

A smaller model is unlikely to:

* Possess better market knowledge than Claude
* Identify hidden information unavailable to Claude
* Discover statistically significant trading patterns

Instead, it often:

* Repeats existing arguments
* Introduces noise
* Creates false confidence
* Generates contradictory reasoning

## Recommendation

Retire or heavily de-prioritise the debate engine.

Replace it with evidence generated from:

```text
Historical trades
+
Entry conditions
+
Exit outcomes
+
Error tags
```

These represent actual market observations rather than synthetic opinions.

Critic B:

Areas for Improvement (Prioritized)
1. High Priority — Address These
A. Intraday Strategy Gap (Biggest Weakness)

The intraday section still relies on daily ATR for stops and targets. This is fundamentally mismatched for 5-minute trading.
Fix: Use 5m/15m ATR or rolling volatility for intraday stops. Target should be dynamic (e.g., next resistance or fixed 3–4% with time stop).

B. Thesis Drift & Entry Tagging

You have the foundation (primary_entry_driver, entry_thesis_summary).
Make this mandatory and visible in the UI (Thesis Check card on every SELL/TRIM).
Compute thesis_drift_score deterministically where possible (signal similarity between entry and exit).

C. Virtual Outcomes Implementation

This is critical to prevent pessimism loops.
Implement the lazy-resolution path in calibration as discussed earlier. Start with a simple version (check if target or stop was hit in the expected window).


2. Medium Priority

Fundamental Pre-Computation: Move valuation and earnings momentum scoring to backend. LLMs hallucinate these numbers too often.
Success Tag Symmetry: You have error tags — add success tags (strong_confluence, etc.) consistently for wins.
Prompt Length Management: 8,700+ tokens is pushing it. Continue aggressive tiering (Tier 1 full detail for urgent holdings, Tier 2 summary for stable ones) and urgency-based sorting.
Calibration Quality Debate (Phase 6): Implement this soon — it will help interpret whether drops are noise or real degradation.


3. Nice-to-Have Polish

Add Sector ETF Relative Strength (not just ASX200).
Implement Fibonacci auto-levels for day-trade signal #4.
Add a "Trade Journal Thesis Review" workflow where you manually rate thesis accuracy on closed trades.
Consider a "Regime Transition Penalty" that temporarily raises confidence floors after a regime flip.
